# ScholarOps synthetic examples

These examples are deliberately fictional. They do not reproduce the maintainer's private research, unpublished work, or confidential data.

Each fixture separates the **input** from the **expected routing / gates / decision**. The expected files are regression expectations, not claims that a native host has already executed the scenario. Native host execution must be recorded separately when it is actually run.

1. [`01-literature-collision/`](01-literature-collision/) — weak neighboring literature vs a true direct collision.
2. [`02-outcome-screen/`](02-outcome-screen/) — resource-allocation screen without an economic-null overclaim.
3. [`03-access-fallback/`](03-access-fallback/) — unavailable licensed data and a construct-changing public substitute.
4. [`04-ai-finance-ladder/`](04-ai-finance-ladder/) — AI capability evidence that does not yet identify market impact.
5. [`05-recovery-evidence-priority/`](05-recovery-evidence-priority/) — a state note that conflicts with stronger artifacts.
